# Bookstore App — Claude Code Context

This is the self-contained bookstore application generated by the SDLC pipeline from requirement `EPMCDMETST-52015` (Add filters to Non-Fiction book search results, parity with Fiction). It is independent of the parent repository's pipeline tooling and can be copied to its own repository as-is.

## Structure

```
bookstore-app/
  src/catalog/      Book data model, filter/sort option catalogs, in-memory seed fixture
  src/search/       Filter validation (allow-list), relative date filtering, query builder + sort
  src/api/          GET /api/search HTTP endpoint + full app server with static file serving
  src/web/          Framework-agnostic filter panel, results view, filter state persistence
  public/           Static HTML/CSS shell for the browser UI
  tests/            Unit, integration, and acceptance tests
```

## How to Build, Run, and Test

Run all commands from inside `bookstore-app/` (not the repo root):

```bash
# Install dependencies (first time or after pulling changes)
npm install

# Run all tests with coverage
npm test

# Type-check without emitting
npm run typecheck

# Compile server-side TypeScript to dist/
npm run build

# Compile browser bundle (dist-browser/)
npm run build:browser

# Start the full app (builds browser bundle first, then starts server)
npm start
# UI available at: http://localhost:3000/
# API available at: http://localhost:3000/api/search?category=fiction
```

## Key Files

| File | Purpose |
|------|---------|
| `src/catalog/book.ts` | `Book` interface and category/format/language types |
| `src/catalog/filter-catalog.ts` | `getFilterOptions()` and `getSortOptions()` — shared across Fiction/Non-Fiction |
| `src/catalog/seed-data.json` | In-memory fixture data (relative publication dates computed at startup) |
| `src/search/query-builder.ts` | `searchBooks()` — applies Filter → Sort → Paginate in that order (DR-013) |
| `src/search/validate-filters.ts` | Allow-list validation; unknown sort values default to `'relevance'` |
| `src/search/date-filter.ts` | Computes relative date cutoffs per request (never cached, per DR-003) |
| `src/api/search-endpoint.ts` | Pure `handleSearchRequest()` handler, testable without a running server |
| `src/api/app-server.ts` | Full server: API + static files (with path traversal protection) |
| `src/web/search-filters-panel.ts` | Presentation logic: Format/Language/Date single-select, star rating, sort select |
| `src/web/results-view.ts` | Wires panel to search function; resets page=1 on any filter/sort change |
| `src/web/filter-state-persistence.ts` | `FilterStatePort` interface + `LocalStorageFilterPersistence` + `InMemoryFilterPersistence` |

## Key Design Decisions

- **Execution order**: Filter → Sort → Paginate (enforced by DR-013)
- **Rating filter**: Exclusive buckets — `3★` means `[3, 4)`, `4★` means `[4, 5]`
- **In-memory catalog**: Seeded from `src/catalog/seed-data.json`; resets on restart (DR-004, capstone scope)
- **Clear All Filters clears sort**: Resets to `undefined`/`'relevance'` (DR-017)
- **Persistence**: `FilterStatePort` with `InMemoryFilterPersistence` for tests; `LocalStorageFilterPersistence` for the browser

## Known Limitations

- **In-memory only**: No database; data resets on process restart.
- **No UI framework**: `src/web/*.ts` (except `browser-app.ts`) are framework-agnostic. `browser-app.ts` is the vanilla DOM reference implementation.
- **Customer Reviews deviation**: Implementation uses exclusive rating buckets instead of cumulative "and above" (by explicit product decision documented in `bookstore-app/README.md`).
